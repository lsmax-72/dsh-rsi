# 原生提炼窗口修复（2026-10-04）

## 问题与修改

固定 PersonaMem 尝试在第 5 个用户首批提炼时达到 4096 输出 token 上限。进一步检查发现，宿主适配将原生默认的 10 条新消息改为整轮长度，本次一次送入 60 条。直接恢复上限会丢失较早消息，因此改为按来源顺序逐批调用原生提炼。

- 使用原生 shouldExtractL1 筛选，L0 仍保存原始消息，不另写过滤规则。
- 每批至多 10 条新消息、至多 5 条前序背景。末批不足 10 条时给出真实新消息数量，避免将背景误标为新消息。
- 每批仍使用原生提示词、去重、冲突处理、向量存储、画像计数与场景连续性。
- 在原有作业 stages 中记录完成位置与存储数；后续批次截断后从未完成位置继续。成功批次写入与作业进度跨存储并非单一事务；进程在两者之间崩溃仍可能重放一次批次，由原生去重处理，不能声称严格恰好一次。
- 记忆阶段全部完成后才调用原生 Skill 提炼。复用核心源码未修改。

## 验证

安装版 DSH 的隔离 profile 使用固定响应与测试嵌入，实际发送真实模型调用为 0。28 条输入经原生筛选保留 27 条；第 2 批模拟输出截断，实际新消息批大小为 10、10、10、7，其中第二批重试一次。第 1 批没有重放，末批不包含被误标的新背景，Skill 等待记忆阶段结束，重启保留完成位置且没有重新调用模型。

原有原生宿主集成检查同时通过：记忆与 Skill 正文进入下一任务、日志重建、画像/场景、版本管理、工作区隔离及预算门。本次不是模型质量结果，也没有重跑或更改已冻结的 PersonaMem 尝试。真实模型小规模验证随后也已完成，详情如下。编程连续学习协议仍需另行冻结。

证据：[批次与重试](evidence/native-memory-batches-20261004.json)，[未完成试验](personamem-independent-incomplete-20261004.md)。

## 真实 Qwen 小规模检查

使用失败用户原始历史的前 20 条消息，另外新建隔离资产与容器；没有摘要、删改消息正文，也没有加载官方答案或评分。学习最多 20 次调用、4096 输出 token 上限，窗口 900 秒；两次读取检查各最多 2 次调用，网关总上限 24。

原生新消息批大小为 10、10，20 个来源消息 ID 全部覆盖且不重复，两批均以 stop 正常结束，输出分别为 930、958 token。作业完成，原生队列及画像触发门通过：工作区 L0/L1/L2/L3 为 20/5/1/1，通用范围为 0/3/1/1。13 次学习与 2 次读取调用合计 74,361 已知 token（学习 61,862，读取 12,499），未知 usage 为 0；15 次模型请求均从原生日志重建，网关匹配。问答没有产生新的学习来源。

本轮没有生成 Skill 候选，因此不能据此声称新 Skill 正文被消费。它验证 20 条输入的修复链，不能证明原来的完整 60 条或任意规模历史都能完成。读取检查未评分，不参与任何准确率提升结论；原来的失败尝试不变。
