## 开发验证与实验边界

旧 20 题已被读取和用于分析，后续优化在这些题上的结果只表述为开发回归。每次开发运行记录代码修订、源组件修订、资产初态、任务与预算。先用小规模任务定位问题，避免七项修复前扩大题单。

PersonaMem 从官方较短上下文版本开始；“较短”不代表现有模型一定能容纳，须核对完整请求容量，包括历史、任务、工具目录和资产。原生导入链路须处理历史会话记录，再由相同 dsh 学习/召回/消费入口运行；不能手写答案资产替代导入。两组使用相同历史截止点，正常基线保留历史，不通过删去基线历史制造收益。开发用户和最终固定用户应分别记录；同一用户多题关联，区间与重采样按用户分组，不按单题假定独立。

连续编程任务使用另行固定的新序列，不能把旧 20 题换个名字当盲测。允许从自然失败轨迹学习；学习输入不能包含官方 gold patch、隐藏 test patch、判分结果或评分器日志。题序、各题初始环境、可见历史、前台/后台额度和 INFRA 重试规则提前固定。成功任务率按预算内保存产物的官方判分计算，同时报告未完成、预算截止及基础设施问题。

## 指标口径

| 指标 | 记录方式 |
| --- | --- |
| 准确率 / 成功率 | PersonaMem 官方任务评分；编程任务官方 resolved；同时给出分母、失败、有效评分和区间 |
| 全链路 token | 分别统计前台、提炼/更新、场景/画像、embedding 可获得用量；所有失败、重试及未知项保留。未提供 token 的本地向量调用报告次数、字符、耗时和用量缺失，不伪造 token |
| 资产相关性 | 保存实际查询、资产 ID/范围/版本/正文、来源任务和后续任务；对固定样本按预定义相关/部分相关/无关及理由复核 |
| 正文长度 | 候选描述、加载正文、实际交付正文分别记录字符与可获得 token；区分入库、召回、加载和真正进入请求 |
| 决策影响 | 将资产建议与后续工具调用、修改或测试选择对应，标注直接支持/相符但因果未证实/无观察证据；模型自称采用不作为唯一证据 |
| 首次有效修改位置 | 记录首次形成通过相应公开检查或最终判分所支持修改的 step、请求序号、累计 token 和时间；初次写文件不自动视为有效 |
| 重复测试和排查 | 规范化命令并保存执行状态、代码状态及目的；区分必要的修后复测与无变化重复，保留次数和成本 |
| 重复错误 | 预定义错误类别并关联先前自然经验；比较序列前/后段，披露任务难度与类型差异，不能把时间趋势直接解释为因果 |

完整交付率属于接入健康指标，不能代替相关性、有效性或质量指标。资产相关性和决策影响需抽样审阅；指标缺失标记为缺失，不能默认为零或有效。
