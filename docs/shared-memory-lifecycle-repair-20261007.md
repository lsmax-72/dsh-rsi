# 通用记忆生命周期修复与验收

2026-10-07。补齐[范围诊断](native-scope-lifecycle-audit-20261007.md)确认的宿主适配缺口。真实 qwen 新增请求为 **0**，旧实验成绩和原始资产保持冻结。此页只报告更新链路与故障边界，不报告答题收益。

## 改动与复用边界

原生工作区 L1 提炼照常执行。宿主保存其完成结果，然后依次让每个当前新条目通过原生 `batchDedup` 与**通用物理库**的候选检查冲突。当前工作区的新 episodic 因此也能修订以前迁走的 persona；不读取其他工作区的专属库。逐条检查使同批后项看到前项更新后的头，避免继续使用已删除的冲突目标。

冲突检索、提示词、决策解析、正文生成、版本计算与 JSONL 写入仍使用固定原生组件。新增 `src/shared-memory.ts` 只负责跨物理库路由、来源 ID 合集、完成前检查和恢复。60 个原生核心文件、10 个复用面板文件的固定修订校验通过，没有修改 vendor 源码。

| 原生决策 | 宿主范围处理 |
| --- | --- |
| store，persona | 原生写入通用库后移除工作区暂存头；迁移采用原生 update 写法，将暂存版本计入新版本 |
| store，其他类型 | 保留原生已写入的工作区头 |
| update / merge | 按原生最终类型写入通用或当前工作区；写入、历史与向量确认后清理被替换头 |
| skip | 删除此次工作区暂存头，保留已有通用记录；persona 与 episodic 都执行 |

固定版本 `queryL1Records` 不实现 `recordIds` 查询参数。适配层在返回行上明确筛选 ID，再向原生 writer 提供对应版本；清理时只删除计划中的真实目标。验收加入同库无关记录，防止把查询返回的全部条目当成删除目标。

## 失败恢复与派生画像

- 每个批次持久化原生提炼结果、各条冲突决策与下一写入位置。冲突调用失败不标为成功，重试不重新提炼已完成批次。
- 新头先写入，旧头后清理。新头携带操作指纹；清理中断后重试核对向量并继续清理，不重复派发冲突调用或增加版本。已经不存在的目标视为完成；仍存在但变化的目标必须重新决策。
- 使用原生检查点的独立操作游标与计数一起原子保存，避免新头已保存、清理失败后漏计或重复计数。
- 修改两个范围的头前标记画像失效。自动召回排除旧派生内容，显式 `profile_read` 返回 `PROFILE_STALE`。原生场景/画像重建后才重新开放；空通用库重建移除旧画像。
- 通用写入和自动通用画像重建串行。管理重建继续要求学习关闭且无运行任务。

这不是跨两个 SQLite 库和 JSONL 的分布式原子事务：写入后清理失败期间可能暂存两个 L1 头，失败作业和失效画像可见，成功恢复后只保留最终头。当前测试覆盖注入异常后的进程内重试，以及完成后进程重启；没有覆盖任意机器断电点或两个进程并发写入。

## 成本与下一步限制

这次修复可能**增加**后台成本：每条原生新头增加一次通用候选检索，有候选时可能派发一次原生冲突判断；同批逐条更新不是一次批量模型调用。每次判断仍经 dsh `prepareCall`、持久化会话、额度预约和 usage 结算，编码费用继续单独记录。画像失效后的完整重建也会增加调用，不能称为 token 优化。

下一步先做有上限的真实跨会话偏好变化小样本，核对原生决策、当前/过去/例外限定语、两类资产实际消费、全链路聊天 token、编码调用及未知 usage。只有确认真实更新质量后，才考虑冻结资产的有限答题诊断；旧 32 题为已曝光开发数据，不能改写旧负结果或重新标为盲测。该真实小样本的输入、停止条件和预算须在首次派发前冻结；本次尚未开始。
