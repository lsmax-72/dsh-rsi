# PersonaMem 当前方法八用户开发复验

## 目的与判断标准
回答一个有限问题：在相同历史、题目、模型和次数/时间预算下，当前完整插件的资产生产与消费能否改善答题准确率，额外花费多少聊天 token。后台已闭合失败后按预登记规则使用已有资产答题，同时报告学习失败。完整交付率、资产数量和页内展示都不能当作质量或效果指标。

这轮值得做，是为了取得当前方法的完整、可核查对照和成本结果；科研上它的价值有限，因为开发已经接触用户、题目及部分成绩。结果无论正负，都只能作为开发复验。之前完整编程八题负向结果及三轮不完整 PersonaMem 结果保留，不用本轮替换。

## 人口边界
[元数据审计](evidence/personamem-replication-population-audit-20261006.json)确认官方 32k 固定版本共 20 个用户、37 个上下文、589 题；只剩身份 1/7/11 没有试跑。保留它们供后续确认，不虚称还有八位全新用户。

本轮完整保留上一轮注册的用户顺序 **9、4、12、14、3、17、19、15**，每人原四题，共 32 道配对题/64 次答题会话，公开历史、截止点、问题选项字节和来源 hash 全部不变。包含曾失败的最后用户，不根据成绩换人、换题、挑选已完成部分。之前七位成绩和资产诊断已经用于开发；第八位失败与开发资源复核也已接触。明确 `independenceClaim:false`。

## 方法与公平性
[具体方案](evidence/personamem-development-replication-proposal-20261006.json)在首次派发前提交并冻结；两组重新使用空白独立 profile。每位基线保留完整相同截止历史，不用剥夺历史制造优势；两组使用相同未知历史时间说明和原 system producer 投影。题目答案仅留评分侧。

启用组使用真实默认导入、L0 捕获、原生 Memory/Skill/画像生产、检索与 Skill 工具。生产原生源码固定不改；当前已验证的正文余量及来源标记属于宿主适配。不给模型植入人工正确资产、不强迫读取不相关 Skill、不向后台回流当前答案或分数。

新冻结选择 [已闭合后台失败策略](personamem-learning-failure-policy-20261006.md)：完整捕获、无活跃调用、队列与请求闭合后，只接受明确 `ABORTED` 或带实际拦截记录的额度失败继续用既有资产答题；失败学习仍单列。未知/基础设施/捕获错误、活跃状态、关闭中断停止。该策略不追溯更改旧失败轮。

与旧轮比较不能分离正文余量、来源标记和失败测量规则的独立贡献，因此只报告“完整当前方法对基线”的差异，不做单项因果归因。

## 固定预算
| 项目 | 本轮规则 |
| --- | --- |
| 模型 | 已配置 qwen3.8-27b，thinking off，provider 重试 0 |
| 前台每题 | 6 次实际调用、120 秒、单次输出 4096 token |
| 启用组每用户后台 | 80 次实际调用、2400 秒、正常完成需 45 秒静默 |
| 原生模型桥/工具步数 | 既有 180 秒/16 步，不延长 |
| 总调用硬上限 | 基线 192、启用组 832；实际请求未用满不补派发 |
| 顺序/并发 | 原顺序逐用户串行；两组顺序交替，同上轮实际运行 |
| 状态隔离 | Docker 审计环境，用户资产独立，评分侧不挂载 |
| 重试 | 0；无救援提炼、后台补时或新题替换 |

聊天 token 的实际消耗取每次模型返回 usage，不将未知/全零算免费。调用数和时限是硬上限，不是另行设定的总 token 硬上限；根据上一轮消耗，预计仍为数百万聊天 token，不能先假设短正文一定省成本。本地向量统计调用/输入字符/耗时，token 缺失明确披露。

## 报告和诊断
- 只有全八用户双组结束才给完整配对平均准确率、差值和 10,000 次固定 seed 的用户分组 bootstrap 区间；该区间描述已接触的开发样本，不能代表未见用户。
- 每题保留官方答案提取结果、真实输出与 stop reason；完全缺失不补零。不完整轮继续抑制完整估计。
- 各用户分列学习完成/已闭合失败、前台/后台已知 token、未知 usage、总已知 token 比例；失败和恢复错误的真实调用全部计费。
- 固定诊断抽样：每位前两道原题、每题前四条实际送达 Memory 引用；全体自然 Skill 的正文、版本、资源和实际加载。标签为直接/部分/无关，记录来源角色、历史阶段/反转、无依据日期、正文长度及实际回答/工具决定的对应。送达不等于影响；有完整历史时不轻率归因于资产。
- 标注在新评分生成前尽量完成，同时声明已有上一轮成绩曝光，不能称人工盲审。无实际引用的样本缺失单列，不拿替换引用补满。
- 只读问答没有代码修改，“首次有效代码修改位置”和官方编程测试次数记不适用；记录检索/加载/重复工具排查次数。连续学习编程诊断沿用已关闭结果，不混入此问答轮。

## 已通过前置与尚存限制
正式启动前已有真实任务官方判分成功、两类资产真实正文消费、原生向量检索与版本链、共同历史/时间和评分隔离回执。新后台失败路径额外通过原生 Docker 夹具：保存 Memory/Skill 后失败仍答完两题，资产正文/版本/资源不变，真实模型 0。

真实短正文资源更新仅有一次局部成功；新日期适配仅有一批真实 L1 样本，无绝对日期错误但场景主语仍错。原生合并与新 Skill 偏好依据的真实质量仍未全面验收。自然 Skill 相关性和总成本可能继续变差。这些是本轮要测量/披露的限制，不把质量未全面正确误报为没有必要测量整体效果。

清洁提交后冻结 revision、源码/构建/脚本、镜像、模型路由、公开输入、官方评分源码和答案文件 hash；分别做两组零派发校验再运行独立新目录 `.artifacts/personamem-development-replication-20261006`。网络不可达或未知运行错误停扩展，记录已消耗费用，不跨预算继续。原三轮关闭目录不恢复，不会因本轮失败再次自动循环换方法。
