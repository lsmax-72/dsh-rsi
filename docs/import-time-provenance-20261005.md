# 导入历史的时间来源核对

状态：已补通用时间来源适配，原生夹具与一个真实批次验证通过；不修改原冻结，不宣称全部内容质量或完整效果通过。

[审计回执](evidence/import-time-provenance-audit-20261005.json)核对用户16保存的全部9条含2026的Memory，并逐条映射原始source_message_ids、导入用户消息和实际提炼请求。对应原文均不包含2026；“上周末”等相对描述被转成绝对日期，部分仅描述经历的原文也得到精确日期。抽样在原结果后进行，只用于开发，不能当盲测相关性标签。

官方输入只有role/content，没有历史时间戳。原生DSH事件时间表示导入发生的时间，宿主captureStored把它映射为message.timestamp；复用原生formatter逐条显示日期，并要求依据timestamp推算绝对时间。因此日期推断获得了一个未标明语义的导入时间锚点。这是可见来源链路与错误共现，不证明每个错误的唯一因果。

修复需要保留原生事件时间与游标排序，同时通过可持久重建的通用来源标记区分导入记录时间和可用的历史日期。再在既有runner适配缝向原生提炼说明未知历史时间的约束；原生formatter、存储和提炼算法保持复用。不得清空所有timestamp破坏增量捕获，也不能把某个用户或某道题的日期写进提示词。下节记录后续最小适配及有界验证；完整PersonaMem仍未完成。
