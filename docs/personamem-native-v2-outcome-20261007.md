## 两类资产的实际消费与质量

固定取每位前两题、每题前四条实际 Memory 引用，共 64 条：**14 直接相关、44 部分相关、6 无关**。全部人工标注在本轮总分生成前保存，但因此前开发曝光，仍不属于盲评。原文、ID、版本、来源序号、哈希、理由均保留。这个样本不是所有召回的质量估计；相关性也不等于事实正确、最新状态或因果收益。

第一请求实际交付的 502 条记忆正文，长度中位数 67、95 分位 165、最大 228 个 Unicode 码点。六个自然 Skill 头正文为 563–1256 码点，中位数 951；实际自然 `skill` 加载 **11 次**，正文进入后续请求 **11 次**，长度 459–1135 码点，中位数 888。记忆主动检索 4 次、原对话检索 8 次、画像读取 3 次；用户 9 的同画像重复读取单列，不能把工具调用数全部算有效排查。

观察到的决策证据及限制：

- 用户 3 的课程题、用户 15 的硬币和投资社区题逐字引用实际 Memory 事实并用于排除选项；证明事实参与判断。完整历史与主动 L0 搜索同时提供同源事实，独立因果收益未建立。
- 用户 12 的研讨会题显式引用所读闲聊 Skill 的简短、共情规则筛选回应。选择的是聊天回应，不能只因外层为选择题就判定 Skill 误用；已保存更正且保留原标注。实际规则使用不自动等于正确贡献。该题官方判对、基线也判对。
- 用户 14 在音乐题自然加载了只针对代码重构的 Skill，这是明确跨领域加载；但该题两组均判对，没有证据证明它导致错误。
- 用户 19 三次读取聊天 Skill 后只输出选项，没有足够推理证据逐条归因；其中投资挑战的历史例证归属写错。正文明确无执行验证，不能包装成已验证成功。
- 用户 17 的 Cosplay 条目省略了原文不喜欢的态度；用户 12 的研讨会合并头未保留较晚正向例外；用户 3 的旅行计划条目未体现后续疲惫；用户 15 的 Memory 保留投资社区阶段对比，Skill 却只保留过去退出。这些是当前事实与时间阶段限制，不因短正文或正确交付而消失。
- 多事件合并头的最新 source IDs 往往只指最后事件，不能单独支撑合并全文；复核需结合原始历史与旧版本。当前报告没有把缺失归属直接认定为凭空生成。

本轮使用原生提炼、混合检索/RRF、Skill BM25 与版本能力。七项装配及后续错误/呈现接线已有回执；资产事实忠实度、阶段合并及适用性仍不保证正确。局部传递成功不能代替整体验证。

## 评分解析与题目质量

官方源码与 `extract_answer` 保持原样，九项虚拟标签控制确认其文本 fallback 不可靠。实际三条尾部格式异常：基线用户 9 第二题明确选 c，但随后解释出现 a/b/d，官方判 false；启用用户 9 第四题和用户 14 第三题包含单一选择加回应正文，官方判 true。原响应、分数、哈希及分类保留，**主结果不重算**。因此 21/32 对 20/32 是官方协议结果，不能解释为无格式因素的纯语义质量差。

原数据也保留两项已发现歧义：用户 12 桌游题 b/d 文字重复；用户 17 第二题问绘画，四项却都谈阅读。未改题、删题、修答案或因此换用户。相反体验可能对应不同事件，不能自动判定原历史错误。诊断和学习输入严格分开。

## 与编程连续学习实验的共同结论

[固定八题连续学习](continuous-learning-outcome-20261005.md)已完成：基线 5/8、启用组 3/8，已知聊天 token 多约 38%；后四题两组都 2/4。39 个保存快照检查、最早有效修改、重复测试候选和日志排查均已报告；固定 15 条 Memory 为 0 直接/4 部分/11 无关，8 题没有自然 Skill 正文加载。PersonaMem 此次有 11 次自然 Skill 加载，也未取得整体优势，不能仅把先前负结果归因未加载技能。

原七类装配修复、小规模开发、完整 PersonaMem 比较和固定编程序列的验证交付已完成；**效果提升目标没有得到支持**。旧20题、已经审阅的编程序列和这八用户均是开发材料。下一步若继续研究，应优先检验事实/阶段保留和任务适用性，并先定义可证伪的有限开发改动；本轮到此结束，不自动换题、扩大规模、补跑失败或再改方法追求正结果。修复与本次完整报告不会自动更新个人桌面进程，管理页和日常使用仍需宿主加载对应构建。
