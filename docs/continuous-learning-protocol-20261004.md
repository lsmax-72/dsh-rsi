## 题单、两组与预算

固定顺序：django__django-11848、11551、12262、11815、11880、11790、11999、11740（后七题保留同一前缀）。它们不在旧 24 次任务清单或已运行开发题中。公开问题、base_commit、源码树、官方评分镜像及解释器版本/日期均已登记。三个官方镜像存在仅文件执行权限的 Git HEAD 差异，经路径/类型/全部 blob 身份核对后沿用已审计的模式处理例外；任务运行时仍要求基线源码树、Django 版本与日期精确匹配。

每题每组使用独立的新当前会话、重置源码。两组各自保留自己的先前原始日志，原始文件可通过正常文件工具查阅，位置说明作为相同的生产者协议；基线没有插件资产。插件组额外保留此前自然生成的资产、作业状态和匹配的原始/学习来源日志。不得复制评分目录、评分输出、gold patch 或隐藏测试给任何求解/学习容器。

第 1 题两组无先前历史，插件资产为空。第 N+1 题恢复第 N 题关闭后的状态，不按官方 resolved 挑选资产，原生未完成检查点也如实保留。两组执行次序按题交替。模型保持 qwen3.8-27b，前台每题每组 40 次调用、1200 秒、8192 输出 token；插件每题新增学习上限 20，序列后台总上限 160，900 秒结算窗口。插件每日调用预算为共享的 160，实验池控制每题新增上限，避免把先前累计调用误算作新题 20 次额度。后台单次原有 4096 输出上限保留。

所有请求/失败/未知 usage 入账；最多一次经过独立证据确认、且尚未有效判分的 INFRA 重试，单独保留并计费，无自动重试。普通未解决、预算截止和自然学习失败不能伪装成 INFRA。来源缺失、协议不匹配、服务异常或评分无有效报告时停止扩大，先审计。

统计逐题 resolved、前 4/后 4 题结果、前台/学习/全链路 token、本地嵌入次数/字符/时间，以及实际交付的记忆引用、Skill 正文和重复加载长度。无变化重复命令按规范化命令和补丁状态区分；零退出标记缺失不自动视为测试通过。旧 2 道开发任务只用于验证读取脚本，不加入新序列分母。
