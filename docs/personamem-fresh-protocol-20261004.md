# 修复后的 PersonaMem 独立用户协议

状态：32 个公开问题及同截止点完整历史已准备，答案只在评分侧；新轮尚未冻结或派发。

## 为什么换一批用户

上一固定轮因原生提炼输出截断停止，4 个用户完成配对，第 5 个用户只有基线，后 3 个未执行。原冻结协议、所有成功/失败和 2,619,938 已知 token 原样保留，不补跑改写旧成绩。随后发现整轮提炼上限覆盖原生 10 条默认窗口，已修复，并用 20 条真实历史在既有 4096 输出上限内通过完整原生链（74,361 token 开发检查，另记）。

原用户中有一人同截止点只剩 2 道未评分题，不能统一补出 4 道新题；另一些用户已用于调试。为避免把已看过的题/用户再称为独立盲测，本轮排除开发用户 0 和上一冻结轮全部用户：2、4、5、6、9、10、12、13。题数、模型、预算不扩大，另外固定同样规模的新用户试验。

## 新题单及选择

使用已固定的官方 32k 原始文件和原评分函数。源文件逐一校验官方固定修订的 SHA。仅按公开用户 ID、同一 context/截止点至少 4 个唯一问题、至少 4 个历史 system 分段形成候选；种子仍为 20261004。打乱候选用户，选 8 个；各用户从固定排序的合格组中随机选择一组，再随机选 4 题。选择不使用官方答案或模型结果，不筛出容易用户，也不因后续失败重抽。

固定顺序：16、18、8、14、3、17、19、15；历史消息数依次为 152、185、211、183、159、180、152、150。题号、截止点、完整历史长度和公开文件哈希见机器清单。模型仍是 qwen3.8-27b，已配置服务只读元信息报告 max_model_len=262144；实际调用容量与错误仍须按请求记录。

## 两组、预算和统计

原运行器和原评分函数保持使用。每用户资产/通用范围独立，两组每题保留相同截止点完整历史及相同 system 背景投影。该投影与官方独立推理脚本角色不完全相同，必须披露。插件先由原生调度学习历史，经严格原生作业、队列/计数及画像触发完成门后冻结学习；四个问题各用独立会话，问题回答排除学习，不向后题泄漏。基线保持正常完整历史。

每题前台最多 6 次、120 秒、4096 输出；每用户后台最多 80 次、2400 秒，45 秒静默，插件网关总上限 104。保持前轮预算，串行运行两组并按用户交替次序，不与编程模型调用并发。新轮失败不自动重试、扩额度或替换题，保留所有已发送成本及未知 usage。

按固定 32 个配对问题报告计数与用户宏平均，配对差的 95% 区间以用户分组 bootstrap 10000 次、同固定种子。8 个相关用户簇使区间粗；不是全量 589 题、跨模型保证或复现其他模型 README 成绩。用户缺失时暂不给完整配对估计，不把学习失败记作答题错误。

诊断仍预定义每用户前两题的前四条实际 Memory 引用：相关/部分相关/无关、来源与回答对应；所有入库/交付/加载长度和 token 自动统计。正文送达或模型自称采用不证明因果。通用 Skill 2738 字符/无资源的既有限制保留，没有通过反复格式审阅获取新成绩。
