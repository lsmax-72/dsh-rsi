2026-10-03；少量真实预演结束，正式配对实验未启动。

## 运行范围

官方 dsh、完整插件与 qwen3.8-27b（thinking off、无 SDK 重试）在隔离容器运行。两个尝试都从空资产库开始，只处理公开 Django 代码；不挂载个人 profile，不提供答案补丁或隐藏测试。保持原生 warmup、每 2 轮或空闲 30 秒、L2 默认延迟和 L3 原生调度，没有手动提炼或点名 Skill。

两次尝试合计最多 25 次 API 调用。第一尝试使用 10 次；修复运行器后仅使用剩余额度，第二尝试 14 次，共 24 次。没有为取得通过提高总额。

## 保留的失败与修正

首次任务确实运行了公开 CommandTypes 测试：35 项测试通过；但两个前台会话都达到额度，未完成最终交付。观察器误把前台 `session/event` 通知当作所有后台会话的必需条件，拦住了后台提炼。两次后台请求在转发前失败，模型网关确认没有对应 API 调用；插件内部有已预留但未发出的用量记录，不能拿它们当真实 token。

修正仅在试跑观察器：前台 flush 官方会话；后台读取模型桥已经 flush 的官方持久日志，核对 `Session.deriveMessages()` 与实际输入后允许调用。没有修改产品后端、原生提炼规则或冻结复用代码。

## 修复后真实结果

源任务使用 3 次调用正常完成：通过真实 Bash 核验 Python/Django 版本及测试入口，用官方 write 工具写出中文 `notes/environment.md`。源任务补丁为 819 字节。

默认捕获/学习生成工作区 L1=2、Skill=1；默认调度另外形成 L2=1、L3=1。原生来源会话任务已完成。另一个消费者结束后的学习记录因 9 次后台上限暂停，保持该状态，不增加预算。

随后恢复初始代码，删除源任务写出的说明文件，创建独立消费者。提示没有指定技能名称；模型第 1 次请求主动调用官方 skill 工具加载 `rsi-django-workspace-env-check`，非错误结果的正文进入第 2 次真实模型请求。两条 L1 正文同时携带正确工作区、ID 与版本进入实际请求，来源 ID 对应真实源会话。

消费者第 2 次请求继续调用 Bash 核验环境，之后达到 2 次前台限额，没有最终回复。自然选择和正文交付已通过，不能把这个会话标为正常完成。L2/L3 本次确认形成，不把它外推为两层完整正文消费均已通过。

全部 24 次请求均可由官方持久日志逐次重建；模型网关确认全部关闭 thinking 且没有 developer role。离线审计没有增加模型请求，机器证据见 [default-flow-preflight-20261003.json](evidence/default-flow-preflight-20261003.json)。完整材料保留在忽略目录 `.artifacts/default-flow-preflight-20261003`。

## 另一个环境差异

任务源码重新 git 初始化后，Django 的开发版本号会取新提交时间；相同代码树不意味着版本字符串一致。当前两次真实预演采用当时的日期，保留原始版本和结果，不改写历史记录。

新运行器要求真实运行显式传入 `--baseline-date`。必须核对评分镜像的实际 HEAD 时间及代码树：该题官方镜像有一个源码不变的新提交，时间为 1786582916；不能直接采用原始基础提交时间 1556608156。两组按评分镜像时间初始化，Django 版本应为 `3.0.dev20260813010156`。断网固定响应另行验证，见 [版本对齐证据](evidence/runner-environment-date-20261003.json)。正式环境准备需对每个题目镜像分别执行此检查。
