# dsh-rsi 产品需求

日期：2026-10-02。状态：讨论共识整理，作为后续实现依据。

本文记录产品约定。当前已有开发实现及固定模型响应的运行时验证，尚未公开发布或运行正式 benchmark；实际验收边界见 [实现进度](implementation-progress.md)。

## 1. 产品定位

面向官方 dsh 桌面版的单用户、本地自动学习插件。通过持续使用积累 Chat Memory 和 Skill，并让后续任务实际使用这些资产，减少重复解释、重复探索和重复错误。

目标是资产层面的进化：记忆持续提取、修正和合并，技能从任务轨迹中创建、更新并复用。资产数量增加本身不足以证明产品有效。

## 2. 首版范围

| 范围 | 产品决定 |
| --- | --- |
| Chat Memory | 保留对话记录、提炼、检索和后续使用的能力，具体复用范围待验证 |
| Skill | 从任务经验中生成、更新技能，保留来源和版本，供后续任务使用 |
| 存储 | 本地持久化，重启后可继续使用，支持导出和清理 |
| 作用范围 | 个人全局和工作区两种范围 |
| 模型 | 默认使用 dsh 已配置的模型，展示额外模型用量并支持学习预算 |
| 管理页面 | 集成在 dsh 插件详情页内 |
| 交付方式 | 可安装的第三方插件，安装后本地运行，无需另外部署完整后台服务栈 |

首版不包含 Wiki、CodeGraph、团队管理、成员权限、Agent 注册和 Task 管理。也不包含模型权重训练、自动修改插件自身源码或自动安装生成的其他插件。

## 3. 日常使用流程

1. 用户在 dsh 插件页面安装并启用 `dsh-rsi`。
2. 用户正常完成任务，插件自动记录允许学习的会话与任务轨迹。
3. 后台按调度规则提炼记忆并创建、更新技能。
4. 后续会话检索相关资产，并通过 dsh 支持的渠道提供给模型使用。
5. 用户需要查看结果、纠正内容或调整配置时，打开插件管理页。

默认自动学习，不要求用户逐条审批生成的资产，也不要求每次资产更新先运行 benchmark。提供暂停学习和手动触发入口。预算耗尽时暂停新的学习调用，已有资产继续可用；具体预算单位和默认额度待实现方案确定。

## 4. 资产范围与目录

| 资产 | 默认范围与处理 |
| --- | --- |
| 个人偏好 | 个人全局，可跨工作区使用 |
| 项目事实、约束和经验 | 当前工作区 |
| 项目技能 | 当前工作区，可由用户提升为通用技能 |
| 通用技能 | 个人全局 |

自进化 Skill 放入 `dsh-rsi` 专属目录，与用户已有 Skill 分开。全局和工作区资产分别管理，具体目录位置待实现方案确定。

用户已有 Skill 可以使用。用户主动选择纳入进化后，复制到专属目录，保留原始来源；后续自动更新管理副本并保留版本。原路径中的 Skill 保持用户维护。

独立目录中的技能必须被 dsh 实际发现、加载和使用。管理页展示成功不等于消费链路已经接通。

## 5. 资产语言

用户可选择资产语言，默认中文。语言设置适用于生成的记忆正文、Skill 自然语言说明和更新摘要；代码、命令、路径、API 名称等技术标识保持原样。

切换语言默认影响后续生成和更新的资产。已有资产提供手动转换，保留转换前版本与来源关系。

## 6. 纠错和恢复

- 记忆可以查看来源、搜索、编辑和删除。
- 用户明确纠正的信息应影响后续学习与使用，避免旧错误反复出现。
- Skill 可以查看内容、更新差异和版本记录，可以禁用或恢复旧版本。
- 修改后的资产必须在后续消费中生效；仅在页面写入成功不足以完成这一需求。

## 7. 管理页面

入口：dsh 左侧「插件」→ 已安装的 `dsh-rsi` → 插件详情页。页面内设置四个标签。

| 标签 | 用户可见内容 |
| --- | --- |
| 概览 | 当前工作区、运行和学习状态、资产数量、最近更新、额外模型用量 |
| 记忆 | 浏览和搜索、来源、编辑与删除 |
| 技能 | 内容、来源、作用范围、更新差异、版本、禁用与回退 |
| 设置 | 插件和学习开关、资产语言、作用范围、模型与预算、导出与清理 |

四个标签已有开发实现。目标桌面 profile 中的完整安装和交互仍需验收；管理 API 和客户端构建已完成独立检查。

## 8. 复用与适配原则

已确认的需求表述：**默认自动学习；优先复用已有的提炼、调度和资产更新能力，适配 dsh 的事件、模型调用及日志约束。具体复用范围通过接入验证确定。**

- dsh 不内置 MemoryCore，插件需要接入宿主事件和生命周期。
- 当前已有的记忆核心源码存在不依赖 Redis 的进程内 MemoryPipelineManager，可作为复用候选；不能因此宣称已经能在 dsh 中运行。
- Chat Memory 与 Skill 的触发链路分别审查。接收会话结束或工具结果事件，不意味着必须重写内部提炼和调度机制。
- 模型调用接入 `ctx.llm.stream()`；原有直接调用提供商的模型调用器需要适配。
- 模型可见输入必须能从会话日志及其不可变引用重建。记录来源会话片段、实际使用的提示词、资产版本、工具定义和调用参数；引用会变化的当前文件或数据库状态不足以保证重建。
- 区分原生复用、宿主适配和新增产品能力；任何暂时替代都应明确标记，不能作为正式评测中的原生复用证据。

## 9. 实现前待确认事项

| 事项 | 需要的证据或决定 |
| --- | --- |
| 复用来源 | 锁定复用组件的来源、版本与提交，识别已有改动，列出保留组件及许可证 |
| dsh 兼容性 | 确认目标桌面版、开发运行方式、插件打包与管理页能力 |
| 原生能力接入 | 证明记录→调度→提炼→资产更新→后续使用能够实际完成 |
| Skill 消费 | 证明独立目录中的资产被实际加载，版本回退影响后续使用 |
| 日志重建 | 证明后台学习与资产注入的实际模型输入可还原 |
| 本地依赖 | 确定存储、检索、嵌入及可选依赖，满足安装后使用的交付目标 |
| 配置默认值 | 确定预算单位和额度、目录位置、语言选项与清理语义 |
