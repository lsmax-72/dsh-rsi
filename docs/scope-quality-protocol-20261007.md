# 三案例真实范围更新质量验收

预登记日期：2026-10-07。目标是验证最近跨范围修复在真实模型下的内容质量和消费，不评估总体准确率或因果收益。固定输入与规则见 [机器协议](evidence/scope-quality-spec-20261007.json)。正式运行前将清洁代码修订、实现哈希、镜像 ID、已配置 qwen 端点哈希冻结到实验目录。

三个独立案例：明确从实体转为数字、转为数字但保留宫崎骏实体收藏例外、卖出重复海报但长期实体收藏偏好未改变。每例先导入旧历史并运行生产队列，生成旧通用画像；再用另一源会话导入补充说明、运行同一队列并重建画像；最后独立消费者保留完整两段历史，经正常资产钩子回答一个问题。案例之间使用独立容器和资产库，顺序固定，每例仅一次。

使用 qwen3.8-27b，thinking off；每例最多20次后台、4次消费调用、600秒；输出上限4096，原生每次工具迭代最多8、超时180秒。完整记录全部后台与前台 token、未知 usage 和原生编码调用。限额、超时、技术失败关闭当前案例，不加额度、不自动重试、不续跑失败状态；其余已登记独立案例照常执行。

复用既有容器 runner、受限模型 relay、原生会话导入、Runtime.process、原生冲突和 writer、场景/画像工具及生产消费者。宿主队列和画像重建由诊断驱动显式调用以保证旧/新阶段顺序，此项不能解释为自动定时调度验收。没有文件/搜索/Bash/PTC 任务工具，没有真实代码执行，也不读取评分器。历史首部加入中性 system 消息，以满足原生 protected surface 首部约束；消费请求保留历史正文，历史 system 正文的投影不声称原角色保持。

评审规则与预期事实留在宿主评分侧，仅案例历史和问题复制入消费者镜像。Skill 原生提炼照常运行，个人偏好文本不强求产出 Skill。此前 Skill 消费回归继续作为其原验收范围的证据。

验收分开报告：

1. 原生导入/实际冲突候选、版本和来源、完整消费者请求与日志重建、答题无学习回流。
2. L1、场景、画像与回答是否保留过去/当前/例外；是否添加无依据事实、把卖出重复物品误当偏好改变。人工正文审阅不冒充盲标。
3. 后台提炼/冲突/Skill/画像和前台各项 token。即使正文改善，若成本增加也如实保留。

零模型夹具先核对入口和证据格式，其生成内容不计质量成绩。夹具开发失败全部保留，不计为 qwen 调用。真实案例任何一层内容不合格均记录具体源文与输出；不能因消费者有完整历史而答对就宣称资产质量通过。全部门槛通过后，才另外登记固定开发题配对诊断；本协议不授权自动扩大题单或开始新正式 benchmark。

夹具入口已通过：[机制与费用](evidence/scope-quality-fixture-20261007/audit.json)、[14 个请求独立游标重建](evidence/scope-quality-fixture-20261007/reconstruction.json)。被篡改输入拒绝；[开发失败](evidence/scope-quality-fixture-20261007/development-controls.json)均保留，真实 qwen 调用为0。含导入助手帧的历史不能按旧脚本“第几个助手帧”推算派发位置，使用实际观察到的 prefixEndSeq 独立重建。真实三例已按冻结协议各执行一次，完成两例、一例后台预算截止；64次请求重建通过，但派生内容质量未全部通过。详见[真实诊断结果](scope-quality-outcome-20261007.md)，本轮关闭，不续跑或扩大题单。
