# 小规模开发验证

旧 20 题已用于诊断，下面所有结果都是开发回归；原首轮冻结数据不回写。

## 任务输入与运行提示

[旧请求诊断](evidence/old20-development-diagnostics-20261004.json)确认 20/20 个首次查询混入同一段 113 字符的固定提示，首次记忆交付均为同一组 3 条资产。实际 Skill 正文加载与候选不同：其中一份通用正文为 7,127 字符，另一份为 1,414 字符。跨请求重复的正文字符只是上下文开销诊断，不是 token 估算，也不证明影响了决策。

[原生关键词对照](evidence/task-query-counterfactual-20261004.json)在旧快照副本上比较混合输入与题目输入：20/20 题结果改变，命中总数 60→22。它只隔离旧版查询问题，命中更少不等于相关性更高，更不能推断成功率改善。原始数据库前后哈希相同。

最小修复：实验运行提示使用正式 agent.inject，source.kind 为 benchmark-protocol；任务正文仍为正式 user 消息。两者均留在实际模型上下文与持久日志，但固定提示不进入任务查询和学习输入。产品前置钩子按最新人类消息检索，不把历次问题拼成查询；对于简短续问，模型仍可按需使用记忆工具，本次不另写意图改写算法。

[安装版宿主验证](evidence/development-query-repair-20261004.json)检查提示确实发送给模型、学习输入排除了提示、实际召回使用任务正文与消息 ID，记忆交付及日志重建仍通过。使用固定响应与明确的编码夹具，真实模型请求为 0。召回诊断保存 query、来源消息 ID、实际交付字符及资产 refs；这些记录供后续相关性与决策审阅使用。

## 精简与执行证据

原生 SKILL_REVIEW_PROMPT 全文保持不变，在末尾追加软性长度目标：通用 SOP 约 1500 字符，保留触发、决策与失败分支；长脚本和夹具使用原生 skill_files_write 资源并引用。没有按字符截断 Skill，也没有重写生产策略或只允许成功任务产生资产。

Skill 的成功断言必须由实际工具结果支持，注明检查及结果；completed 轮次、计划和助手自述不算执行证据，失败/部分验证也可保留。L1 原生输入仅含用户与助手正文，因此追加明确条件：助手结果只能记录为自述/未验证，不能编造测试通过。工具结果仍由原生 Skill 分支消费，L1 算法及消息格式保持不变。

[原生调用验收](evidence/extraction-guidance-20261004.json)证明完整生产提示词、角色标记、资源接口条件与 L1 自述限制实际送达；采用夹具返回值，不能证明真实模型遵守或资产质量提高。

尚待：少量隔离真实任务检查产物、消费与成本；PersonaMem 预演；新编程序列。

## 少量真实运行安排

[运行清单](evidence/development-run-manifest-20261004.json)在运行前固定两道旧题：11095 → 11119。首题空资产，次题仅继承首题自然产生的资产及原生持久会话。每题前台最多 30 次、后台新增 10 次（两题同一持久日额度 20 次）、15 分钟及 90 秒观察窗；使用已配置 qwen，不按分数补跑。本阶段只有 RSI 开发检查，不据此报告相对提升。

工具结果保存对应 patch 哈希、请求序号及时间；变化的 patch 另存只供评分侧审阅。首次编辑不自动称为首次有效修改；须结合公开检查、最终判分及保存的修改轨迹确认。脚本不能自动判定资产对决策的因果影响，相关性和决策证据继续人工复核。

隔离镜像直接安装已锁定的原生依赖，将固定 GGUF 复制为只读镜像文件；没有开放宿主绑定或任务网络下载。新容器固定响应检查通过原生本地模型加载、实际文件工具、任务输入、学习队列和日志重建；不属于真实任务效果验证。

没有观察到测试框架执行命令；第一题没有行为测试，第二题执行了 4 次内联 Python 行为检查：第 17 次复现因 TemplateDoesNotExist 失败，第 18 次核对 Context 自动转义，第 19 次复现错误转义，第 21 次修复后输出三个预期转义结果。它们不能遗漏为“没有测试”。相同代码状态下完全相同的 shell 命令重复次数为 0，但这不等于没有冗余排查。同一目的的不同命令仍需人工审阅。两个 resolved 不是独立盲测准确率，也没有基线，不能报告提升。完整跑完/产出文件不计作质量。

管道暴露的实际问题：L0 的串行编码在 Linux AMD64 模拟环境较慢，加上提炼和 Skill 工具循环，90 秒不足以让所有资产在下一题开始前就绪。首题关闭前 snapshot/export 与最终持久库不同，诊断以关闭后的数据库副本和完整模型账本为准。后续协议应预先设有界的学习完成观察窗，未完成必须保留为未完成；不为本轮追加额度或改写结果。外部流量闸门拦下的尝试与继承预算槽位另记，不与已发送请求或未知 API 用量混为一谈。

## 独立自然消费检查

两题均未加载 Skill，所以另行提前记录了 [最多 6 次前台/0 次后台的消费计划](evidence/natural-asset-consumer-plan-20261004.json)，不加入编程成绩。第一次被公开任务 ID 守卫在派发前阻止，模型请求为 0；修正 ID 后，相关问题没有指定资产名称，模型自行调用 skill，正文实际进入第 2 次请求，同时首请求已有真实记忆 refs。

[消费回执](evidence/natural-asset-consumer-20261004.json)：4 次模型调用、0 后台、40,695 token，持久日志重建通过；实际加载正文 2,782 字符（不含 frontmatter）。模型随后调用原生原始会话/场景工具核对，指出先前只有编辑记录、没有 runtests/py_compile 结果，将验证列为待做。它给出了资产与可观察决策的对应证据，仍不构成因果或效果提升。

据真实样本追加必要条件：一次性功能请求不属于未来任务的长期指令；场景以用户活动而非 AI 自述命名；Skill 明确分开 Evidence（已执行及结果）与 Validation（建议检查），不能把未执行的扩展步骤写成已验证流程。原生提示全文和算法保持不变。条件送达的夹具已通过；真实分类复核另记，不把夹具当作生成质量证明。

[真实 L1 分类复核](evidence/development-memory-classification-20261004.json)将首题原始持久会话导入全新资产库，仅调用一次原生 L1：生成 1 条 episodic，没有将 get_inlines 需求当作长期 instruction，来源消息 ID 保留。本次 8,071 token；前一次因缺少现有 provider 的 reasoningEfforts 映射而输出截断，10,841 token，失败记录保留。两次共 18,912 token，不加入两题编程成绩。真实复核只证明该样本分类，不保证所有场景分类正确。

[证据约束送达夹具](evidence/development-evidence-guidance-20261004.json)验证追加条件实际进入原生 L1/Skill 提示；Skill 的新 Evidence 段生成质量仍需下一次正常学习检查。独立消费与分类复核共 59,607 token，另于两题 1,071,786 token 列出，开发检查已知合计 1,131,393 token。

命令诊断现在关联原始 tool/result 的消息 ID、事件序号和实际输出；保留宿主 toolIsError 与非零退出码标记两个不同字段。第 17 次 bash 虽 toolIsError=false，原文仍含 [exit code: 1]，属于失败的复现尝试，不算通过验证。没有成功退出码标记时记为缺失，并按实际输出审阅预期行为，不从 isError=false 推断成功。

## 资产内容质量审阅

[统一判读回执](evidence/development-asset-review-20261004.json)区分相关性、实际交付、决策对应和内容质量。首题功能需求对模板题无关，对独立同类钩子问题相关；score=0、优先级或同属 Django 不是相关性判定。Skill 正文在第 2/3/4 次请求各交付 2,782 字符，共重复 8,346 字符；这是正文开销证据，不是 token 估算。其领域较窄仍不自动说明足够精简，正文超过通用 SOP 的 1500 软目标。

发现已复现的内容错误：[公开反例](evidence/modeladmin-contract-diagnostic-20261004.json)。Skill 将 admin.get_inlines(None) 写作必做步骤，声称调用处没有 request；真实调用处为 to_field_allowed(self, request, to_field)。消费者一面重复 None 建议，一面提出 get_inlines 中 assert request is not None。隔离容器中原始源码处理该公开调用返回 False；保存补丁后触发 AssertionError。没有使用隐藏测试、官方答案或模型；原任务官方 resolved 回执保持不变。说明资产交付与核对意识已经得到验证，资产内容质量仍不合格，不能把“能消费”当成“经验正确”。

这些资产产生于 be66e7e 及其原有指导条件，早于后续明确分开 Evidence/Validation 的追加条件；不能用旧产物直接判断新条件的真实生成效果。反例和审阅留在评分/诊断侧，不写回学习来源或旧快照。后续须按固定样本检查新产物，而不能只检查是否出现 Evidence 标题。环境验证已与内联行为检查分开：第二题仍是 4 次行为检查，额外的环境确认不算行为测试。

## 调用契约与验证覆盖的通用约束

根据公开反例，只在原生 Skill 生产提示之后补充通用条件：保留实际签名中的调用参数契约；读过或改过调用处，不足以证明同名访问都必须替换；跨调用处的未验证修改作为待验证假设；通过检查只支持其覆盖行为。不加入特定任务答案，不回写旧资产，也不改原生提示前缀或算法。[送达夹具](evidence/native-caller-contract-guidance-20261004.json)通过，真实模型请求 0；这仅证明条件进入提炼请求，尚不证明新生成资产的内容质量通过。
