# 首轮正式配对实验结果

实验开始：2026-10-03；报告更新：2026-10-04（Asia/Shanghai）。

本轮插件组多解决 2 题。配对差异区间包含 0，不能据此声称稳定收益。

固定 4 个前序、20 个后序，两组共 48 次执行。模型 qwen3.8-27b，thinking off，冻结实现 `99af6ba2d10250d2950dc08983211feac5cdf69b`；没有事后改题、筛资产或追加任务重跑。判分采用固定官方 SWE-bench 3.0.0。

## 用户中断样本与敏感性结果

† 11087 经用户明确暂停后，用官方会话 resume 与“继续。”恢复，前台只用剩余额度，后台沿用原预留；官方结果两组均失败。原 20 次输入可重建，其中一次响应和最终 usage 缺失，旧网关日志缺失；后续 30 次请求的网关和重建均通过。原材料、未知成本和这项协议差异完整保留，未算为 INFRA 重试。

按续跑判分前宣布的敏感性规则，排除 11087 整对后，基线 8/19、插件 10/19；差异 +10.5 个百分点，95% 区间 [-10.5, 31.6]。主结果固定 n=20 保持原值。
敏感性成本保留全部前序、排除该整对：基线 11,277,178 token，插件 17,722,622，精确增量 6,445,444（+57.2%）；前序成本按敏感性 n=19 摊销。

## 机制与完整性

前序自然生成 L0=127、L1=3、L2=1、L3=1、Skill=5，没有人工补写、筛选或改正。后序插件执行中，前序 Chat Memory 正文交付 20/20，Skill 正文交付 20/20，两类均交付 20/20；用户提示未点名生成 Skill。核验的是 ID/版本/完整正文到达真实模型请求，候选名称不算正文消费。L2/L3 生成已观察，其独立全文消费未单独验收。

20 份后序初始资产与官方 sessions 副本均等于同一冻结清单 `028b42b5705219eadc3fbf3ea1f5dceacd92c1c61c24811c613634dc7955a6bf`，前序源文件哈希不变，后序新增资产不跨题传播。20 个基线执行的插件工具、候选、注入隔离通过；各任务运行时代码树、Django 版本及冻结实现核对通过。前序后台实际 40/100 次，后序每题后台均不超过 10 次。

官方镜像仅权限差异的准备恢复保留逐文件审计与限定 image ID 的接缝记录；原 Dockerfile 仍 reset 到公开 base_commit，运行器在调用模型前检查实际基础树与版本。零真实调用环境控制不计入 48 次正式执行。

## 解释边界

这是一个仓库、一个模型、一个固定小题单上的整体插件比较，不能推广为跨仓库稳定收益，也不能分别归因于 Chat Memory 或 Skill。成功率、成本和正文交付要一起解释；机制真实运行不等于效果提升。完整 input/output token、请求数、停止原因、墙钟与每条证据哈希见 JSON 回执；原始请求、资产、官方判分保存在本地忽略目录 `.artifacts/formal-paired-20261003`。
