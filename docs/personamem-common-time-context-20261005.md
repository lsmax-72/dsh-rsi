# PersonaMem 两组共同历史时间说明

这是新方法的宿主数据语义适配，旧冻结、请求和结果不变。历史事件仍使用真实导入时钟与原生日志游标，原始历史role/content及截止点保持。

此前导入时间来源标记已进入原生L1提炼，但答题请求中的原始历史没有明确说明原消息时间未知。现在实际运行器两组都调用同一个personaHistoryContext函数：保留原历史system背景，并说明事件时间是导入元数据，不应与当前日期一起充当历史活动的日历锚点；源正文的明确日期保持，其余相对时间不臆造绝对日期。说明没有用户、题目、正确选项或专用年份。当前问题仍是正常user来源，说明仍标记为personamem-history；评分与答案不进入学习。

[原生验收](evidence/personamem-common-time-context-20261005.json)包含两种明确夹具：

- 官方开发用户的完整152消息/147原始用户和助手消息，5原生作业、18次提炼夹具、25次总夹具请求；持久日志重建、时间来源标记与完整历史交付通过。
- 实际四题Docker运行器两组使用相同5消息开发前缀。基线4次、启用组6次夹具请求（其中2次学习），全部可重建；共同历史与时间说明哈希一致，启用组原生学习settled，答题学习隔离通过。只读根目录、无宿主绑定及内部网络策略核对通过；未创建真实模型网关。

新增真实模型请求为0。短前缀运行器夹具不能证明完整历史的模型容量、准确率或资产质量。说明已在实际请求和回执中记录，后续必须用新方法冻结，不修改旧实验请求。
