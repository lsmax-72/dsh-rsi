## 修正内容

统一入口原先固定使用 `preflight`。该值适合单次夹具，不能直接用于多题前序：原生队列按 `sessionId:turn` 去重，恢复资产后重复 ID 会把另一题当作已有任务。现在增加 `--instance`，同步用于会话 ID、证据目录、回执和预算结算路径。真实运行显式给 ID 时，在前台调用前核对公开 task.json 的 instance_id，错题镜像直接报错。

资产快照与官方会话日志必须一起恢复。新增 `--seed-sessions`，与 `--seed-assets` 成对使用，仅复制实验自己的 sessions 子目录，不复制 credentials、个人 profile 或其他宿主配置。构建前核对资产库 sources 及 learning-runs 所指向的官方会话全部存在，并保存输入文件 SHA256。缺少来源会话时拒绝启动，不通过重写资产或忽略恢复错误绕开。

以上均为实验运行器适配，产品 State、原生队列和记忆/技能算法未修改。来源快照从已停止并导出的实验卷取得，包含错误资产与未完成任务，不能手工删掉后再比较。

## 参数与正式准备约束

后续单次入口使用 `--instance TASK_ID`。需要经验时另传同一次导出的 `--seed-assets STATE/assets --seed-sessions STATE/home/sessions`；原始组两项都不能传。不同题使用不同 ID，重试从该题原定输入快照恢复，不能把失败尝试的新资产带进重试。

另一个正式配置约束：资产快照保留原生 dailyCallBudget 和历史 usage。外部每题新增额度不能让原生已耗尽的日预算自动恢复。正式建议统一将原生日预算上限设为允许值 100000，由已验证的宿主共享池严格限制前序 100 次、后序每题 10 次新增调用；不是允许发送 100000 次模型请求。前序与全部后序副本保持该设置一致，不能靠删 usage 或改资产文件清空历史。该配置进入待确认方案，尚未用于真实实验。

额外断网检查在独立夹具副本内构造 100 条当天历史 usage，原生日上限为 100000、宿主新额度为 0。前台正常结束；原生新增一次预留，但实验入口在实际请求前拦住，后台实际调用为 0，共享池最终结算为 0。来源日志核验和输入重建通过。历史行仅为控制数据，原生预留数 101 不代表 101 次真实调用或 token 消耗；未改写任何真实资产。见 [历史预算检查](evidence/history-quota-20261003.json)。
