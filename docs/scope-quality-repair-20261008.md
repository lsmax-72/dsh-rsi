# 范围与派生内容修复、三例开发复验

2026-10-08。前轮三例暴露的问题分别是旧工作区 instruction 与新通用 persona 并存、L2/L3 无来源推断、Skill 名称被当作 ID 导致多余查询。本次沿用原生模块，只修正宿主适配和原生策略参数；复用核心及面板源文件校验全部通过。

## 改动与边界

- `shared-memory.ts` 将当前工作区与通用库的原生向量候选交给原生 `batchDedup`。同一编码模型下按原生 cosine 分数合并 top K；不重新算分，不比较不同物理库的 BM25 分数。该第二次冲突检查要求已验证的向量路径，不降级为跨库 FTS；正常消费者 hybrid/RRF 召回保持原生。排除当前及同批尚未处理的新条目，避免提前合并后又复活；其他工作区始终不可见。
- 原生模型仍决定 store/merge/skip 和最终类型。writer 适配按目标的物理范围读取历史版本，合并来源 ID，先持久写入目标，再删除旧头；现有恢复标记、检查点和画像失效保护保留。旧版本保存的计划兼容默认通用目标。不能保证模型每次都作出正确语义决定。
- `skill-prefix.ts` 仅在原生 list/search 返回副本的展示名称旁附真实 skill_id/version；原生工具绑定原 core，存储名、frontmatter、描述、正文、排序、版本与查询次数不变。覆盖全量、相关、最近及无前缀四分支。实际能节约多少模型调用仍待复验。
- `profile-strategy.ts` 通过原生 `memoryPrompt` 接口调整 L2/L3 归纳关注点：仅有来源事实、变化与例外，不补性别/人格/动机，不将记录时间当活动日期；无依据洞察留空。原生 Scene/Persona 提示、Markdown/META、工具和路径约束继续保留。此前已有时间与事实提示，此次加强为明确的事实选择策略；提示不是确定性事实校验器。
